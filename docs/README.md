# StudySphere — Design Thinking Documentation

This folder contains the Design Thinking documentation for the StudySphere project, prepared to address the first-review evaluator feedback.

## File Index

| File | Purpose |
|------|---------|
| [01-Empathy-Portfolio.md](01-Empathy-Portfolio.md) | Empathy stage: background, target users, a user-research template (with placeholders for real interview data), research findings, and an empathy map. |
| [02-Defined-Problem-Statement.md](02-Defined-Problem-Statement.md) | Define stage: problem context, user problem statement, "How Might We" question, user needs, and measurable success criteria. |
| [03-Ideation.md](03-Ideation.md) | Ideate stage: brainstormed ideas, comparison table, selection criteria, and the rationale for choosing StudySphere as the final concept. |
| [04-AI-Interaction-Audit.md](04-AI-Interaction-Audit.md) | Audit of all AI functionality actually present in the codebase: the AI Assistant page, the Supabase Edge Function, prompts, modes, limitations, and ethical considerations. |
| [05-Prototype-and-Validation-Report.md](05-Prototype-and-Validation-Report.md) | Prototype overview, fidelity, a test-participant table (pending real testers), usability test tasks, a feedback collection template, and an iteration log. |
| [06-Design-Thinking-Reflection.md](06-Design-Thinking-Reflection.md) | Reflection on each Design Thinking stage, what was learned, what would be improved, and future iteration plans. |

## How to Update After Real User Testing

1. **01-Empathy-Portfolio.md** — Conduct interviews with at least 3–5 students using the provided template. Fill in every placeholder field (Participant ID, date, observed behavior, frustrations, needs, goals, quotes, key insights). Replace the empathy map placeholders with real observations. Populate the "Research Findings" section with aggregated themes.
2. **05-Prototype-and-Validation-Report.md** — Recruit at least 3 testers. Fill in the "Test Participants" table with names/initials, dates, and status. Observe each tester completing the listed tasks and fill in the "Feedback Collection" table. Populate the "Findings" sections (positive feedback, usability problems, feature requests, confusing areas, performance issues) with real data. Add rows to the "Iteration Log" for every change made in response to feedback.
3. **06-Design-Thinking-Reflection.md** — Update the "What Would Be Improved" and "Future Iterations" sections based on what the testing revealed.
4. **02-Defined-Problem-Statement.md** — Revisit the success criteria after testing to confirm whether they were met.
5. **04-AI-Interaction-Audit.md** — Update if AI functionality changes or if testers report AI-specific issues.

## Important Notes

- **No fabricated data**: All research and validation sections contain templates and placeholders, not fabricated results. They must be filled with real data after conducting actual interviews and usability tests.
- **Codebase accuracy**: The AI Interaction Audit (04) documents only features that actually exist in the StudySphere codebase as of the current version.
- **No application modifications**: Creating these documentation files does not modify any existing application code, database schema, authentication, or AI functionality.
